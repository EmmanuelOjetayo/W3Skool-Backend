# W3Skool — Backend LMS & Course-Commerce Engine

Production-grade RESTful API and domain engine for **W3Skool**, a modern technical academy and Learning Management System (LMS) with course commerce powered by Flutterwave.

---

## Architecture Principles

1. **The Backend is the Single Source of Truth:**
   - Course ownership, enrollment state, sequential unit unlocking, video watch completion, quiz scoring, and certificate eligibility are strictly calculated and authoritative on the server.
2. **Idempotent Financial Transactions:**
   - Flutterwave checkouts and webhooks use compound uniqueness and transaction status locks. Duplicate webhooks or double-redirects never create duplicate enrollments or charge duplicate records.
3. **Bandwidth-Optimized Media Architecture:**
   - Videos and documents are hosted via Cloudinary. Uploads occur **directly from the browser to Cloudinary** using cryptographically signed params generated by the backend (`/admin/uploads/signature`), preventing multi-gigabyte media streams from clogging the Node.js event loop.
4. **Anti-Cheat Progress Tracking:**
   - Video progress reports are accumulated with duration caps and monotonicity guards, preventing students from manipulating timestamps or client-side completion flags.

- **Cloudinary Account**: Cloud name, API key, and API secret

## Installation & Setup

1. **Navigate to the Backend directory:**
   ```bash
   cd Backend
   ```

2. **Install dependencies:**
   ```bash
   npm install
   ```

3. **Configure Environment Variables:**
   Copy `.env.example` to `.env`:
   ```bash
   cp .env.example .env
   ```
   Fill in the required configuration:
   ```env
   NODE_ENV=development
   PORT=5000
   MONGO_URI=mongodb+srv://<username>:<password>@cluster.mongodb.net/w3skool?retryWrites=true&w=majority
   JWT_SECRET=super_secret_cryptographic_key_at_least_32_characters_long
   JWT_EXPIRES_IN=7d

   # Flutterwave
   FLUTTERWAVE_PUBLIC_KEY=FLWPUBK-xxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxx-X
   FLUTTERWAVE_SECRET_KEY=FLWSECK-xxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxx-X
   FLUTTERWAVE_ENCRYPTION_KEY=xxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxx
   FLUTTERWAVE_WEBHOOK_HASH=your_webhook_secret_hash_configured_in_dashboard

   # Cloudinary
   CLOUDINARY_CLOUD_NAME=your_cloud_name
   CLOUDINARY_API_KEY=your_api_key
   CLOUDINARY_API_SECRET=your_api_secret

   # Frontend
   CLIENT_URL=http://localhost:3000
   ```

4. **Start the Development Server:**
   ```bash
   npm run dev
   ```
   The API will be available at: `http://localhost:5000/api/v1`  
   Health check endpoint: `http://localhost:5000/health`

5. **Start in Production:**
   ```bash
   npm start
   ```

## API Summary

All endpoints conform to the uniform envelope `{ "data": ... }` on success, or `{ "error": { "code": "...", "message": "..." } }` on failure.

For complete integration details, request bodies, query parameters, and code examples, consult [`FRONTEND_API_GUIDE.md`](./FRONTEND_API_GUIDE.md).

### Base Route Groups

- **Auth:** `/api/v1/auth` (`/register`, `/login`, `/me`)
- **Public Catalog:** `/api/v1/courses` (`/`, `/:idOrSlug`, `/:courseId/units/:unitId/preview`)
- **Payments:** `/api/v1/payments` (`/initiate`, `/verify`)
- **Webhooks:** `/api/v1/webhooks` (`/flutterwave`)
- **Student Learning:** `/api/v1/student` (`/dashboard`, `/courses`, `/courses/:id/outline`, `/units/:id`, `/units/:id/progress`, `/quizzes/:id`, `/live-sessions`, `/courses/:id/certificate`)
- **Admin Management:** `/api/v1/admin` (`/stats`, `/courses`, `/modules`, `/units`, `/quizzes`, `/live-sessions`, `/students`, `/payments`, `/uploads/signature`)
- **Public Verification:** `/api/v1/certificates` (`/verify/:code`)

## Production & deployment

`DEPLOYMENT.md` (repo root) is the source of truth for running W3Skool outside
local development: environment variables, Render blueprint setup, GitHub push,
production checklist and operational notes.

Quick reference:

```bash
# local
cd Backend && npm run dev && npm test     # 49 verification checks
cd Frontend && npm run lint && npm run build

# production (Render reads render.yaml)
API    : rootDir Backend  -> npm ci && npm start   (health: /health)
Web    : rootDir Frontend -> npm ci && npm run build -> dist (SPA rewrite /* -> /index.html)
```

The API validates its environment at boot and refuses to start when a required
variable is missing; it also shuts down gracefully on SIGTERM and trusts the
Render proxy so rate limiting stays correct.
